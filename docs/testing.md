# Testing and code coverage

How Traceability Service runs its tests and measures coverage (SCRUM-42, reused for SCRUM-123). The other Wonrich services follow the same pattern; the last section is a copy-and-adapt checklist.

---

## Test projects

| Project | Kind | What it covers |
|---|---|---|
| `tests/TraceabilityService.UnitTests` | Unit | Logic in isolation, no I/O. Fast (seconds) |
| `tests/TraceabilityService.IntegrationTests` | Integration | The real API through HTTP (`WebApplicationFactory`) against a throwaway MySQL started by Testcontainers. Also proves EF Core migrations run on an empty database |

They are separate projects, and separate **named CI stages**, so a slow integration failure is never confused with a broken unit.

```bash
dotnet test tests/TraceabilityService.UnitTests            # fast feedback while coding
dotnet test tests/TraceabilityService.IntegrationTests     # needs Docker running locally
```

The integration tests need Docker Desktop; Testcontainers starts `mysql:8.0` and removes it afterwards. No connection string or `.env` is needed: the container's own connection string is injected into the app.

Kafka is not available in CI, so the Kafka health check reports **Degraded** there. That is asserted by the tests rather than worked around.

## Coverage

| Item | Value |
|---|---|
| Collector | Coverlet (`--collect:"XPlat Code Coverage"`) |
| Settings | `coverlet.runsettings` (Cobertura format; excludes `Migrations` and generated code) |
| Report | ReportGenerator merges the unit and integration runs into one report |
| Threshold | **60% line coverage**, enforced in CI; a drop below it fails the build |
| Artifacts | `coverage-report` (HTML), `test-results` (`.trx`) |

EF Core migrations are excluded because they are generated by tooling; including them would measure the generator, not the team's tests.

### Where to read it

| Where | What you see |
|---|---|
| Pull request comment | Coverage summary table, updated in place on each push |
| Actions run summary | The same table |
| **Test results** check | Every test, with failures readable in the UI rather than the raw log |
| `coverage-report` artifact | Full HTML report: download, open `index.html`, drill into per-file and per-line coverage |

### Changing the threshold

`COVERAGE_THRESHOLD` in `.github/workflows/ci-cd.yml`. It is 60%, the same as the other services, so they are comparable; agree any change with QA first.

---

## Adding tests

- **Unit:** add a class to `tests/TraceabilityService.UnitTests`. No database, no network, no Kafka.
- **Integration:** add a class to `tests/TraceabilityService.IntegrationTests` marked `[Collection(ApiCollection.Name)]` (one shared MySQL container), take `TraceabilityApiFactory` in its constructor, and call the API through `factory.CreateClient()`.

Fix a failing coverage check by adding tests, not by lowering the threshold.
